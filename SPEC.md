# Lane pack format — `lanepack/1`

A **certified lane pack** (`*.lanepack.tar.gz`) is the sellable unit of
mtlm-router: a calibrated decision lane for one domain, with its measured
evaluation and operating point included — not just a weight file.

## Contents

| file | what |
|---|---|
| `<lane>.head` | trained head weights (LR over pooled trunk taps, mhd format) |
| `manifest.json` | name, version, taxonomy, `metrics`, `status` (`certified`\|`demo`), `live_verified` (bool), `provenance`, `license`, `pricing` (`{tier: free\|commercial, ...}`), `head_sha256`, `runtime` requirement |
| `eval.json` | the eval report: holdout accuracy, n, OOS recall/AUROC, conformal operating points, taps |
| `labels.txt` | one `route :: description` per class |
| `LICENSE.txt` | artifact license |

## What "certified" means

The manifest carries a **leak-free holdout eval** (head emitted from train
rows only, scored through the served runtime) and, when calibrated, a
**conformal operating point** (`qhat` + expected selective risk). A pack
without these is a demo pack, not a certified pack.

`live_verified` records that the head was loaded in a real `anvil-serve`
and probed in/out of scope before packaging — `lane_pack.py` *refuses*
`--status certified` without it, because offline eval cannot catch
train/serve skew (the civic-0.2.0 incident: green offline, garbage live).
Older certified packs are grandfathered — `lane_verify` reports them with
a warning, not a failure.

`demo` means: synthetic or partial corpus, live-verified but **not** a
production claim — read `eval.json`'s honesty notes before quoting numbers.

## The `oos` class convention

Intent/domain lanes SHOULD ship an explicit `oos` (out-of-scope) class in
the taxonomy — the abstention path for inputs matching no route. Eval then
reports `oos_recall`, `id_oos_recall` (in-domain-adjacent OOS),
`far_oos_recall` (topically distant OOS) and `in_scope_false_oos`. Tone or
sentiment lanes use their natural negative class instead (e.g. `neutral`
in `eq_tone`) — do not bolt a redundant `oos` onto a negative class that
already carries the semantics.

## Registry — `index.json`

`index.json` at repo root (generated by `build_index.py`, never hand-edited)
flattens every published pack: name, version, url, tarball + head sha256,
taxonomy, status, `holdout_acc`/`n_holdout`, `oos` metrics block,
`live_verified`, conformal points, license, runtime. The builder
normalizes the eval key variants used by different emitters
(`holdout_acc` | `in_scope_holdout_acc_trainonly` | `in_scope_acc_trainonly`).
`tools/lane_install.py` (in mtlm-router) consumes it:

```sh
python3 tools/lane_install.py eq_tone --appliance <appliance-dir>
# resolves latest version, downloads, verifies shas, writes models/, prints env
```

## Registry sidecars — `floors.json`, `deprecated.json`

Two checked-in policy files sit next to the packs; `build_index.py`
merges them into index entries. Packs stay immutable — operator policy
and lifecycle state live here, not inside tarballs.

**`floors.json`** — recommended confidence floors, keyed by lane *name*
(spans versions):

```json
{"clinc150": {"min_conf": 0.7, "note": "7.8% leak / 69% coverage at 0.7"}}
```

→ index field `operating`. `min_conf: null` means no useful floor
(argmax abstain or conformal carries the lane). Re-measure after any
head/corpus change (`bench/oos_eval.py`).

**`deprecated.json`** — additive yank records, keyed `name@version`:

```json
{"helpdesk@0.1.1": {"superseded_by": "helpdesk@0.2.0", "reason": "..."}}
```

→ index fields `yanked`, `superseded_by`, `yank_reason`. A yanked pack
stays installable by exact pin (immutability) but is excluded from
latest-resolution, shows a badge on the catalog, and `lane_install`
warns with the migration path on both `--apply` and `--check`.

## Install a lane

```sh
tar xzf clinc150-0.1.0.lanepack.tar.gz
# add to your appliance env:
export ANVIL_EXPERTS="clinc:./clinc150_mt3.head,$ANVIL_EXPERTS"
# if eval.json carries a qhat, gate it:
export ANVIL_EXPERT_QHAT="clinc:<qhat from eval.json>,$ANVIL_EXPERT_QHAT"
```

## Versioning

`<name>-<semver>.lanepack.tar.gz`. Minor bump = retrain/recalibration that
keeps the taxonomy; major bump = taxonomy change (not drop-in safe).

## Selling vs free

Packs marked `license: Apache-2.0` and `pricing.tier: free` are free.
Commercial packs ship the same format with a commercial `LICENSE.txt` and
`pricing` in the manifest — projected into `index.json` so terms are
visible before download. Certification is what you're paying for:
the eval, the operating point, and the support loop. See PRICING.md.
